# Application Binary Interface

Status: Pinguer has **no stable ABI**. Section 1 describes the representation
the v0.1 compiler will use (**Normative (v0.1)** only in the sense that the
v0.1 compiler must be internally consistent); it may change in any release.
Sections 2–4 are **Proposals**.
Implementation: not started.

## 1. v0.1 data representation

| Type | In memory | In LLVM IR (registers) |
|---|---|---|
| `bool` | 1 byte, `0` or `1` | `i1` |
| `i8`/`u8` … `i64`/`u64`, `int` | natural size and alignment, little-endian on all supported targets | `i8` … `i64` |
| `f32`, `f64` | IEEE 754 | `float`, `double` |
| `char` | 4 bytes, a Unicode scalar value | `i32` |
| `string` | pointer to UTF-8 bytes + length in bytes (`u64`); not null-terminated | `{ ptr, i64 }` |
| `()` | zero-sized | no value; `void` return |

A program must never observe a `bool` byte other than `0` or `1`, or a `char`
outside the scalar value range; the compiler relies on these invariants.

## 2. Calling convention

* Pinguer functions use LLVM's default calling convention and **internal
  linkage**: they are not visible outside the executable. Their calling
  convention is unstable.
* The process entry point is a C-compatible `main` function generated by the
  compiler. It initializes the runtime, calls the Pinguer `main`, flushes
  output and returns exit status 0.
* **Proposal:** `extern "C"` functions use the platform's C calling
  convention and a stable, unmangled symbol name
  ([INTEROPERABILITY.md](INTEROPERABILITY.md)).

## 3. Symbol names (Proposal)

Once multiple modules and packages exist, symbols must be unique across a
program. The proposed mangling encodes package, module path, item name and
generic arguments with length-prefixed components (similar to Rust's v0
scheme), prefixed with `_P`. A demangler will be part of the toolchain.

## 4. Stability (Proposal)

A stable ABI for Pinguer-to-Pinguer calls is **not planned** for the
foreseeable future: it would freeze data layouts and block optimizations.
Binary compatibility across compiler versions is provided only through the C
ABI. Libraries are distributed as source packages.
